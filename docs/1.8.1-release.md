# MundusMaker 1.8.1

This patch addresses Mac startup trouble reported on 1.7 and adds optional
Docker / NAS hosting. All 1.8 map and handout features remain included.

## Mac launcher

The JXA launcher passed JavaScript `null` into Cocoa's file-attributes arguments.
Foundation expects a dictionary or native `nil`; the incorrect bridge value
can raise `-[NSNull count]: unrecognized selector` before the server starts.
The launcher now supplies real empty dictionaries and native `$()` nil values,
and explains failures preparing the support folder or startup log.
[Apple's JXA bridge reference](https://developer.apple.com/library/archive/releasenotes/InterapplicationCommunication/RN-JavaScriptForAutomation/Articles/OSX10-10.html)

Replace the old **MundusMaker.app** with this release and open it from Finder.
No Node installation or Terminal startup is required. Worlds and settings stay
in `~/Library/Application Support/MundusMaker` or the custom folder you already
selected. Unsigned-build macOS approval may still apply.

Tests reproduce the reported exception with the former call and check startup,
filesystem errors, port selection and the menu's quit confirmation. These are
bridge-contract tests on Windows; native macOS launch, including the tester's
exact OS and M1 Max, remains unverified.

## Optional hosting

The universal ZIP now includes a Dockerfile, Compose project and
[NAS setup and migration guide](docker.md). A required password protects every
route, and a persistent volume preserves campaigns, assets, library packs and
recovery history across restarts and rebuilds. Docker manages the data location;
Settings and the welcome tour explain hosting and DM access.

The desktop server remains loopback-only. The container gateway checks browser
origins, forwards revision checks intact, and closes if its local backend dies.
The 5etools downloader still requires explicit consent. Use a private VPN or
HTTPS reverse proxy for access away from home. The password grants full DM
access; player preview does not provide a restricted player account.

Verification includes automated gateway/authentication, persistence, asset,
library, conflict and download-consent tests against the actual Node server,
plus an isolated-browser smoke test. Docker image build/runtime testing requires
a Docker host and was not available on the Windows release environment.

One **MundusMaker-1.8.1.zip** still covers Windows, Apple silicon/Intel Macs,
and Linux x64/ARM64. Archives exclude contributor instructions, test data,
password files and private configuration.
