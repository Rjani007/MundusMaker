Welcome to MundusMaker

One download for Windows, Mac and Linux. Extract the whole ZIP, then use the launcher for your system below. It chooses the bundled runtime automatically; you do not need to know your processor type or install Node. Your browser opens http://localhost:4870; worlds stay on your computer.

macOS: double-click the app

  1. Move MundusMaker.app to Applications, then double-click it. The app works on Apple silicon (M-series) and Intel Macs with macOS 13.5 or later. Startup does not need Terminal or a separate Node installation.
  2. The MM menu offers Open MundusMaker, the startup log, and Quit MundusMaker. Closing the browser leaves the local server running. Wait for the browser’s Saved indicator before quitting.

The familiar Start-MundusMaker.command is included too; it opens the same app. Double-click the app itself to avoid a Terminal window. The app contains everything it needs, so it can be moved out of the extracted folder.

This tester build is unsigned and has not been notarized. If macOS blocks it, first try opening the app, then use System Settings → Privacy & Security → Open Anyway, if offered. Follow Apple’s instructions; no Terminal commands or global security changes are needed. Managed Macs may require administrator approval.

Worlds default to ~/Library/Application Support/MundusMaker/data. Configuration lives beside that folder; the MM menu can open it. Logs live in ~/Library/Logs/MundusMaker. Replacing the app leaves these folders intact.

Saw “-[NSNull count]: unrecognized selector” on 1.7 or 1.8? Version 1.8.1 corrects the launcher argument responsible for this error. Replace the old app with this release and open it from Finder. Keep your Application Support folder and worlds as they are.

Updating an older portable Mac build? Quit the old server, launch this app, and use Import to select your old MundusMaker folder (the Mac app keeps its own data folder, so it does not look beside itself). This copies worlds and leaves the originals in place. If you previously configured a custom data folder, choose it in Settings. Keep the old folder until you have checked your imported worlds.

Windows

Open Start-MundusMaker.bat. MundusMaker starts in the background, puts a MundusMaker icon in the Windows tray (the arrow by the clock may be hiding it), and opens your browser. Closing the browser does not stop it. To stop it, use Quit MundusMaker from the tray icon or from Settings in the app; saves in progress finish first. For an optional permanent installation with Start Menu and Desktop shortcuts, open Install-MundusMaker.bat. If something goes wrong, MundusMaker-Console.bat runs it in a window that shows every message. Windows 10 or later, x64.

Linux

Launch start-mundusmaker.sh using your file manager’s Run option, or run ./start-mundusmaker.sh from that folder. It selects the bundled Intel/AMD x64 or ARM64 runtime automatically. It starts MundusMaker in the background and opens your browser, so you can close the terminal; stop it with Quit MundusMaker in Settings. ./start-mundusmaker.sh --install-desktop adds MundusMaker to your applications menu, and --foreground runs it in the terminal instead (Ctrl+C stops it), which shows every message. Requires glibc 2.28 or later and kernel 4.18 or later. The archive carries executable permissions for both launcher and runtimes.

Your worlds and this release

Windows and Linux portable builds save to data beside the launcher unless configured otherwise. Upgrading: extract this version next to your older MundusMaker folder (for example, both inside Downloads) and start it. The first time it starts, it copies your worlds from the older folder by itself and tells you what came along. If it finds more than one older folder, or one that keeps its worlds in a synced folder, it asks you instead. Quit the older version first. The older folder is never changed, so you can delete it once you have checked your worlds. You can also copy worlds later from the Import page. Never replace your data with the sample folder.

Docker / NAS: This download also includes Dockerfile, compose.yaml, and the hosting guide. Set up the password file, then build with docker compose up -d --build. A persistent data volume keeps your worlds across updates. Use a private VPN or HTTPS proxy for remote access. The password grants full DM access, including secrets.
