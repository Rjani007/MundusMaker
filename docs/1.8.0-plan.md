# MundusMaker 1.8.0 — maps worth keeping, handouts ready to share

## Intended result

A DM can build a coherent world → region → town chain, improve its geography
and settlements without losing their edits, and turn campaign material into
convincing player handouts in the same local app.

Two release demonstrations define success:

1. Generate an archipelago with mountain ranges and sensible rivers, drill
   into a coastal province and its capital, edit the harbor and districts,
   then export matching maps at useful print resolution.
2. Create an aged book, a signed letter, a scroll and illustrated item cards;
   link them to campaign entries; keep a GM annotation private; preview and
   export the exact player versions as PDF or images.

## Map generation priorities

| Area | Change | Acceptance evidence |
| --- | --- | --- |
| World geography | An opt-in generation version with shaped continental plates/ridges, coherent mountain chains, varied coastlines, drainage basins, lakes and tributaries; climate follows latitude, elevation and prevailing moisture | Seed gallery shows meaningful archipelago, continental and inland-sea presets; rivers follow drainage and reach a sink; the same seed/settings repeat exactly |
| Regional maps | Preserve parent coastline, elevation, rivers, lakes, settlement identities and capital position; add local detail and terrain-aware roads with passes, crossings and bridges | The same province and town agree across both drill paths; no duplicate capitals, underwater inherited towns or roads crossing open water without an explicit crossing |
| Towns | Streets create blocks and parcels; placement follows the coast/river, slope, gates and landmarks; districts have distinct density and building use | Harbor, river, hill, market and fortified towns are visibly different and have readable streets, sensible waterfronts and editable district names |
| Interiors | Building-purpose presets with room adjacency, entrances, circulation and furnishing rules | Tavern, manor, temple and workshop floor plans have reachable rooms and usable doors; furniture does not block every route |
| Dungeons | Purposeful entrance/goal placement, room roles, loops and branches, reliable stairs and optional encounters/keyed rooms | Every required area and floor is reachable; several viable layouts per preset; no orphan stair pairs; no encounter becomes public through the map key |
| Cartography | Consistent palettes, line weights, symbol scales, label priorities, legend and distance scale across levels | Print samples stay readable at normal size; labels avoid important features; parchment, clean atlas and ink-saving treatments are clearly distinct |

Start with world/region geography and town structure. These produce the largest
improvement to existing campaigns. Interiors and dungeons follow within the
same release once the shared preview and edit-preservation work is stable.

### Generation and editing contract

- Freeze every existing generator path. New behavior needs explicit version
  metadata or a new style; absent fields on old maps retain the old behavior.
  Never change the defaults used to interpret an existing map.
- Give new algorithms their own RNG streams. No additional draw may enter an
  existing stream. Keep classic world generation frozen.
- Apply user edits after generation has consumed its streams. Stable site keys
  must survive renames and position changes. Inherited sites retain origin,
  seat, capital and town-seed provenance.
- Keep carved regions self-contained. Updating from a parent remains an
  explicit action with a preview of what changes.
- Add generation previews with **Apply** and **Keep current map**. Warn about
  affected generated-site links before a destructive regeneration; preserve
  custom sites, strokes, labels and linked entries wherever possible.
- Expose controls through `MAP_KINDS` and its hooks. The generic editor should
  not accumulate branches for individual map kinds.
- Introduce undo/redo for map editing transactions, layer visibility in the
  editor, and selection/movement of placed objects. Temporary editor layer
  visibility is not a new secrecy flag and must not change export visibility.
- Run heavier generation in a local worker where practical, with cancellation
  and progress. Rendering and file export must remain local and usable without
  network access.

### Quality and performance gates

Capture the existing fixture hashes before touching a generator, including
coastal towns, classic worlds, edited atlases and carved regions. Old fixtures
must remain byte-identical. Maintain a separate fixture gallery for the new
generation version, with assertions for drainage, road continuity, room
connectivity and stairs.

Measure on a documented, ordinary laptop. Targets: immediate input feedback,
normal edit previews within one second, and a typical world preview within
three seconds after warm-up. Slow exports must show progress and remain
cancellable. Inspect both screen previews and 4× PNG/PDF renders; do not accept
an attractive thumbnail with unreadable print output.

## Handout creator

### First release templates

| Template | Controls and output |
| --- | --- |
| Old book / journal | Cover, title, author, chapter headings, automatic page flow, optional drop cap, page numbers, margins and worn-paper treatment |
| Letter | Sender, recipient, date, body, closing, signature, local seal image and restrained paper aging |
| Scroll | Title/body, decorative border, parchment treatment and single- or multi-page layout |
| Item cards | Local illustration, title, description, visible properties, campaign links, card size and multiple cards per printable page |
| Notice / wanted poster | Headline, portrait, body, reward/footer and readable display typography |

Each template opens with useful example structure and a live player preview.
Users can change typography, paper, ink, borders and spacing without editing
code. Keep decorative effects adjustable and provide an ink-saving version.
Text must remain selectable in PDFs. Local images retain their aspect ratio,
and text flows around only the layouts explicitly supported by the template.

### Data and privacy model

- A handout is an ordinary entity, with the existing `gmOnly`, block `secret`
  and relation `secret` fields. Add the built-in Handout category through all
  three normal sites: default types, sample world and additive migration.
- Keep prose in ordinary blocks. Store presentation choices and block-ID
  placement in an optional `entity.handout` object; do not maintain another
  copy of the handout's text inside a template.
- A `HANDOUT_KINDS` registry owns template defaults, editor controls, preview
  and export behavior. Reuse existing local asset upload, save, history,
  backup/restore and entry-link mechanisms.
- Links to source characters, items or locations store entity IDs. Resolve
  visible content when rendering. A hidden or deleted target must not leak a
  previously cached name, portrait or property into a player handout.
- Apply the same content filter before browser preview, print layout, PNG
  export and PDF export. GM annotations can be secret blocks. No new privacy
  flag, cloud rendering, remote font service or account is needed.
- Bundle only original or correctly licensed fonts, ornaments and textures,
  with attribution recorded. Prefer procedural local paper textures and the
  project's own SVG decorations. User images come from `/assets/`.

### Sharing workflow

**Choose template → write or select existing material → style → preview as
player → export.** The preview must use the same pagination and content model
as export, with warnings for missing local images or text that cannot fit.

Provide A4, US Letter and suitable card sizes, single-handout PDF, a selected
handout packet with ordered pages, and per-page PNG output. Offer useful image
resolution controls and an ink-saving print preset. GM exports are explicitly
labelled, and every secret continuation repeats the GM banner.

Build pagination around measured text and shared layout primitives, using the
existing jsPDF vendor for PDF output. Do not screenshot the editor and call it
a print export. Unicode/font support and long paragraphs are part of the
prototype gate, before investing in ornamental themes.

## Delivery sequence

| Milestone | Concrete deliverable | Exit condition |
| --- | --- | --- |
| 1. Baselines and examples | Legacy hash fixtures, representative slow-map measurements, and four handout content fixtures | Existing generation and exports are repeatable; real-world text lengths and page sizes are documented |
| 2. World/region engine | Versioned terrain, hydrology and terrain-aware roads, with inherited sites intact | New gallery meets geography checks; every old fixture remains unchanged |
| 3. Towns and cartography | Parcel/street generation, functional districts and readable map styling | Harbor/river/inland acceptance examples work through both drill paths and print cleanly |
| 4. Editing and remaining scales | Regeneration preview, edit undo/redo, interior adjacency and dungeon topology improvements | Cancelling changes nothing; applying preserves supported edits; room and stair checks pass |
| 5. Handout vertical slice | Entity model plus one polished letter and a multi-page book, with real player PDF/PNG output | Long text, page breaks, local images, missing assets and secret content all behave correctly |
| 6. Remaining templates | Scrolls, item-card sheets, notices and ordered handout packets | Each template has a worked example, keyboard-accessible editing and readable print samples |
| 7. Release hardening | Sample-world demonstrations, in-app help, migration checks, offline and export review | All old-map hashes, save/recovery tests, visibility checks, layout inspections and packaging checks pass |

Stages 2 and 5 can be developed independently once the contracts from stage 1
are settled. Integration order should follow these gates rather than a fixed
calendar estimate.

## Required regression scenarios

- Open old maps with no version metadata, edit a label, export and verify their
  underlying generated geography has not changed.
- Drill world → town and world → region → town; compare name, seed, coast/river
  context and linked entity identity. Rename from both ends of the chain.
- Regenerate a preview and cancel; apply a new preview with custom sites and
  linked locations present; verify each retained edit and broken-link message.
- Render a book with long paragraphs and headings, an item with a very long
  name, missing/portrait/wide images and international character names. Check
  page boundaries, text extraction and high-resolution output.
- Put a secret block on a public handout; link a hidden entity; then delete a
  linked target. Confirm that UI player preview, every PNG page and PDF text
  all omit the protected content.
- Back up and restore a world with handouts and assets into a separate world.
  Check block references, local asset rebasing, relationships and history.
- Test with networking disabled. Inspect tester archives for accidental data,
  development files, and any `AGENTS.md`/`CLAUDE.md` at any depth or casing.

## Scope boundaries

MundusMaker remains a local preparation tool. Live shared maps, fog-of-war
presentation, token movement, cloud sharing and AI-generated images are outside
this release. Procedural maps, editable handouts and reliable player exports
are the focus. Template marketplaces and an unrestricted desktop-publishing
canvas can wait until the first templates and print engine are dependable.
