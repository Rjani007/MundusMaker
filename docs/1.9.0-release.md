# MundusMaker 1.9.0

Design record: [1.9.0-plan.md](1.9.0-plan.md). This note says what shipped,
how it was checked, what was not checked, and the decisions taken where the
plan left a choice open.

## Install and upgrade without a terminal

- Every launcher starts MundusMaker without a lasting window: a tray icon on
  Windows (`Start-MundusMaker.bat`; `MundusMaker-Console.bat` is the old
  visible window), the menu-bar app on Mac, a background process on Linux.
  Quit is graceful everywhere: saves in progress finish first.
- A busy port is identified before anything is touched: the same MundusMaker
  opens, an older one or another program is named.
- On first start, worlds from one older MundusMaker folder beside the new one
  are copied in automatically; anything ambiguous waits for a choice. The old
  folder is never written.

## Share what the players know

- **Player wiki**: an offline website in a ZIP, player edition only, with
  entries, relations, backlinks, the timeline, player maps with their keys,
  handout pages and search. It opens from `file://` with networking off.
- **Reveal to players** with a per-session log and undo.
- **Safety check** before every player export.

## Maps you can run

- **Map keys** on dungeon rooms, settlements, landmarks and region hexes, with
  unplaced notes, re-anchoring, promotion to an entry and a GM PDF key.
- **Populate** a 1.8 or modern town from original role tables.
- **Journey planner** on region maps: roads and ferries, days by pace, clock
  advance, a session note and ephemeral daily rolls.
- **Modern towns**: four layouts (downtown grid, suburban sprawl, waterfront,
  river town), a night palette, editable street and place names.

## Character sheets players recognize

A **Familiar layout** for D&D 2024, Vampire: The Masquerade V5 and Call of
Cthulhu 7th edition, on screen and in the PDF, from one section map per
system. The standard and compact layouts remain; the familiar one is opt-in
until testers approve it.

## Smaller features

Party panel (DM Screen and Encounter), unlinked mentions, map-fragment
handouts, session handout packets, second-folder backups and sync-conflict
compare.

## How it was checked

- `npm test`: 118 automated tests, including new suites for the wiki text
  layer (canary world), reveals and the safety check, populate, journeys and
  the campaign clock, modern towns, familiar sheet section maps, mentions and
  party values, second-folder backups (including rotation beside foreign
  files and a copy-only restore through the server) and sync-conflict adopt
  and discard.
- `npm run test:render`: 60 map hashes. The 17 legacy and 34 earlier 1.8
  baselines are unchanged; new fixtures cover a keyed dungeon (its player
  render is byte-identical to the unkeyed one) and each modern layout.
- `scripts/wiki-check.js` (part of `npm run test:wiki`): exports the sample
  world's wiki through the app, opens every page from `file://` in headless
  Edge with networking disabled, checks every link, image and the search, and
  greps every file and file name for the sample's GM-only names, secret block
  text, entry ids and uploaded file names (48 probes, 0 hits).
- In the app (scratch data): reveal and undo round trip, the pre-export safety
  dialog, key tool with repaint → unplaced → re-anchor → promote, populate
  twice without duplicates, a journey applied and undone, modern town
  creation with renames and keys, packets across a reload, unlinked mentions
  on sample text.
- Familiar sheets were rendered to PDF (A4 and Letter) and screenshotted page
  by page, and the in-app version was compared with the print.
- Before the commit (2026-09-29): every module imports in the browser; every
  screen of the sample world opened in GM view and in player preview without an
  error; copies of the owner's five worlds opened on every screen, entry and
  map (425 in all) without an error; the player PDFs (standard and familiar)
  held none of 29 secret strings the GM PDF held; the Timeline screen and PDF
  agreed in order and date strings, including two entries in the same month;
  and a backup with its images restored into a separate world kept map keys,
  the reveal log, the handout packet, the party, travel paces and the town era,
  with image paths moved to the new world.

## Not verified

- Tester review of the familiar layouts against each publisher's current free
  sheet, on screen and on paper (the plan's acceptance condition).
- Firefox and Safari opening the wiki from `file://` (Edge was checked).
- Native Mac and Linux launches; the Windows tray's busy-port message boxes
  were not clicked through.
- The 2,000-entry scale targets were measured on generated data in Node
  (projection and wiki pages ≈ 0.2 s, safety check ≈ 0.1 s), not end to end
  with map images in a browser.
- A full `npm run package` build (it downloads the Node runtimes); the
  packaging tests pass and the new server module is in every allowlist.
- In the app, only by automated tests: the second-folder backup card in
  Settings, the sync-conflict Compare dialog and a journey that crosses a
  ferry (the sample region has none).

## Decisions taken

- **Era for drilled towns**: towns opened from a world or region map follow
  the world default on the Maps page (`world.townEra`), unless that map sets
  its own under "Towns opened here" (World default, Historical or Modern).
  Every town map also has its own Era parameter, and "Modern town map" can be
  chosen when creating a map.
- **Map key notes** default to secret blocks on the map's own entry, with
  Promote to entry.
- **Reveal log session**: the Encounter view's last choice, else the most
  recently updated Session; the dialog lets the GM change it or not log.
- **Player wiki** is player edition only. **Populate** tables are
  system-neutral. **Journeys** work on region maps only.
- **Second-folder backups** run only for the data folder the app chose itself
  (never one named on the command line or in the environment, which is how
  tests and previews run), and never in Docker.

## Licensing record for the familiar layouts

This follows the 0.12 licensing line. For each system: which terms apply,
what the layout relies on, and what the owner should confirm before the
layouts become the default.

| System | Terms | What the layout uses | To confirm |
| --- | --- | --- | --- |
| D&D 2024 | SRD 5.2 / 5.2.1, CC-BY-4.0, covers the rules text the app already bundles | Section names, field names and arrangement of a character sheet; values from the character's own data; no logo, art, border or font; the attribution prints on the sheet's continued details | The SRD does not license the sheet's visual design; the layout copies arrangement only. The banner names the game ("D&D 2024") descriptively, as the app already does |
| Vampire: The Masquerade V5 | Dark Pack agreement (Paradox Interactive), already used for the creator and the Dark Pack logo in Settings → About | Section names and arrangement; dots and damage boxes drawn from primitives; no logo on the sheet | Whether the Dark Pack terms allow more (such as the Dark Pack logo on the printed sheet); if so, use exactly that and credit it |
| Call of Cthulhu 7e | Chaosium's Fan Material Policy, already cited in About | Section names, skill names with base values (math only), number tracks drawn from primitives; no Chaosium logo or art | That the printed sheet should carry the fan-material notice; it currently appears in About, not on the sheet |

The UI calls it the "Familiar layout" and never "official"; About says the
layouts are drawn for MundusMaker and are not official sheets. An exact
official look remains possible later by filling the GM's own copy of each
publisher's fillable PDF (the plan's alternative), which redistributes nothing.

## Also in this build: 2.0 preparation

Added after the notes above, before the 1.9.0 package was built (AGENTS.md,
"Official sheets, keyboard access and update checks", has the details).

- **Official sheets.** `📄 Official sheet…` fills the GM's own copy of a
  publisher's fillable sheet. D&D 2024 and both Call of Cthulhu sheets can be
  downloaded from the publishers' own sites on request; the release carries
  none of them, because every one allows personal use only. V5, which Renegade
  hands out through a store checkout, gets MundusMaker's own look-alike.
- **V5 familiar layout** redrawn from Renegade's sheet (cream page, double
  frame, the official arrangement on both pages) and now the default for V5
  sheets; layout choices are remembered per game.
- **Keyboard and screen readers** on every rating, damage track and slot row.
- **Check for updates** in Settings → About, inactive until package.json names
  a GitHub repository.
- **Running windowless, visibly.** ⏻ Quit in the top bar; a tray notification
  on start; a bar when the app was updated while running; and an optional
  stop a set time after the last tab closes.
- **Packaging.** The release no longer carries `docs/`; the Docker and data
  safety guides ship as DOCKER.md and DATA-SAFETY.md.
